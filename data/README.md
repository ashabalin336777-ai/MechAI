# Синтетический датасет для агента «Цифровой механик» (ИИкузница)

> **Все данные синтетические.** ТС, VIN, госномера, ФИО, даты, измерения, номера запчастей и документов вымышлены.
> Значения не предназначены для реального ремонта. Автомобили в данных обезличены: `LCV-3.5t` с двигателем Cummins ISF 2.8 (`ISF2.8s4R148`, 110 кВт).

Датасет покрывает всю цепочку агента: диагноз ML-сервиса → карточка двигателя и история дефектов → поиск процедур и нормативов в мануалах → сверка с отклонением и оценка риска → уточняющий вопрос механику → черновик заявки на дефектовку → отправка в ТОиР **только после подтверждения человеком**.

## Цепочка (как данные связаны между собой)

```
get_ml_diagnosis        ml_responses/*.json            (схема v1.1)
get_engine_card         engine_cards.json
get_defect_history      defect_history.json
search_manuals /        manuals/chunks.jsonl           (СР-ISF28-ДЕМО, СБ-ISF28-ДЕМО-01, РТО-ГН-ДЕМО)
get_manual_page
ask_mechanic            mechanic_dialogs.json
draft_defect_request    defect_requests/Sx_draft.json  (статус draft_awaiting_confirmation)
submit_defect_request   defect_requests/S1_confirmed_submitted.json (confirmation_token, confirmed_by, статус submitted)
оценка агента           golden_scenarios.json
```

Связность: `engine_id` / `vehicle_id` / VIN / пробег / моточасы одинаковы во всех файлах сценария; `ml_analysis_id` в заявках равен `analysis.analysis_id` ML-ответа; все цитаты в заявках — дословные фрагменты страниц из `manuals/chunks.jsonl` (проверяет `tools/validate.py`).

## Что изменено в схеме ML-сервиса (v1.0 → v1.1)

- `schema_version` = `1.1.0`.
- `meta {synthetic, scenario_id, note}` — пометка синтетики.
- `analysis.trigger` — причина записи (жалоба водителя, плановая проверка и др.).
- `recording.quality.rerecord_instructions` — как повторить непригодную запись.
- `overall.requires_rerecord` (bool).
- `severity` (в `overall` и `faults[]`): добавлено значение `undetermined`.
- `urgency`: добавлено значение `recording_invalid` (запись непригодна; **это не `can_operate`**).

## Ключевые «ловушки» (проверяют рассуждение, а не поиск похожего текста)

- **S1:** бюллетень СБ-ISF28-ДЕМО-01 заменяет предел 0,110 мм на 0,095 мм при пробеге > 250 000 км; нормо-часы ×1,2 (СР стр. 14-01) → 19,56 н/ч; интервал масла по СБ 5 000 км (просрочен на 600 км); в истории есть жалоба на давление масла от 2026-09-19 без повторного замера.
- **S2:** в карточке пусто `fuel_filter_last_change`; сначала сторона низкого давления (СР стр. 08-02), форсунка — только при утечке > 40 мл/60 с.
- **S3:** рост RMS 3,3 → 4,1 мм/с = +24 % (< 40 %), зона не повышается; срок проверки зазоров по регламенту автопарка 80 000 км, а не 90 000 км руководства.
- **S4:** в ответе ML есть слабые гипотезы (`piston_slap`, `knock_detonation`) с уверенностью < 0,1 — их нельзя выдавать за диагноз.
- **S5:** работы по патрубку наддува не нормированы в стр. 14-01, номеров патрубков нет в каталоге — агент не должен их выдумывать.

## Правила HITL, заложенные в данные

- Черновик имеет `status = draft_awaiting_confirmation`, `request_id = null`, `confirmed_by = null`, `confirmation_token = null`.
- `submit_defect_request` допустим только после события UI: `S1_confirmed_submitted.json` содержит `confirmation_token` (выдан UI, привязан к `draft_id`), `confirmed_by`, `confirmed_at`, `submitted_at`, `request_id`, статус `submitted`.
- Флаг «запрет выезда» агент не ставит: `ban_flag_status = awaiting_toir_responsible` (РТО-ГН-ДЕМО, стр. 05-01).
- Соответствие срочностей: `can_operate` ↔ `low`, `inspect_this_week` ↔ `medium`, `inspect_immediately` ↔ `high`, `do_not_operate` ↔ `stop` (аргумент `urgency` в `draft_defect_request`). Приоритет заявки по РТО-ГН-ДЕМО стр. 06-01: `critical / high / normal / low`.

## Как проверить

```bash
cd agent_data
pip install jsonschema rfc3339-validator
python3 tools/build_all.py      # пересобрать и провалидировать
python3 tools/validate.py       # только проверка
```

Проверяются: валидность ML JSON по схеме v1.1 (с форматами uuid и date-time); согласованность зоны и срочности с СР стр. 12-03 и 12-04; существование каждого `page_id` и дословность цитат; коды работ и номера запчастей из каталога руководства; пересчёт нормо-часов; совпадение идентификаторов между файлами; монотонность истории; корректность черновика и отправленной заявки; ссылки в `golden_scenarios.json`.
