# MechAI

**MechAI** — AI-агент «Цифровой механик» для диагностики ДВС парка НейроДВС (ЯМЗ-236М2, ЯМЗ-536, ЗМЗ-5234.10, ЗМЗ-40904.10/40905.10). Механик выбирает машину и проверку и нажимает «Получить результат диагностики». Агент объясняет вердикт ML, находит этапы работ в руководстве на двигатель этой машины со ссылкой «документ + страница PDF» и по команде механика создаёт заявку в ТОиР.

Проект хакатона «ИИкузница», трек «Цифровой аватар», заказчик ООО «НейроДВС». Все данные синтетические (заглушки и парк ТС из `mock/`, компонент заказчика). Не использовать как реальные данные ремонта.

**Стенд:** https://ashabalin336777-ai-mechai-3580.twc1.net (версия задеплоенного кода: `/health`, поле `git_sha`).

**Версия MVP:** тег `mvp-final`. История вех: [CHANGELOG.md](CHANGELOG.md). Текущее состояние по этапам: [docs/STATUS.md](docs/STATUS.md).

## Что сделано

- **Агент F1–F7:** LangGraph, инструменты `get_vehicle`, `get_diagnosis`, `search_manual`, `get_history`, `draft_ticket`, `create_ticket`. Заявка уходит только по одноразовому `confirm_token`, привязанному к хэшу показанного черновика. Заявка не создаётся при `check_failed`, при `normal`, без ссылок из руководства этого хода и при ответе «нет инструкции».
- **RAG по руководствам:** гибридный поиск (pgvector + полнотекст + реранк), фильтр по двигателю в коде инструмента, порог `RAG_MIN_SCORE` = 0,80. Страницы-рисунки (сканы) распознала vision-модель: около 64 из 72 страниц, текст лежит в базе с `source='ocr'`. Код распознавания удалён в релизе; его хранит тег `mvp-ocr-ui`.
- **Проверка цитат кодом:** каждая цифра с единицей в ответе должна дословно стоять во фрагменте этого хода и иметь ссылку `[обозначение, стр. N]`. Неверная ссылка заменяется кодом, непроверенная фраза убирается.
- **Противоречия руководств:** известные расхождения из `data/known_conflicts.yaml` показываются механику обеими формулировками со ссылками, без пересказа моделью.
- **Голос:** ввод через `whisper-1`, язык по умолчанию русский (`STT_LANGUAGE`); пустое значение — автоопределение. Аудио не сохраняется: в журнал пишутся модель, длительность, стоимость и код ошибки, байтов записи нет.
- **Мобильный интерфейс:** вёрстка 360–430 px без горизонтального скролла, цели касания от 48 px. Режимы «Стандартный», «Новичок», «Крупный». Первая карточка ответа — вердикт «светофор»: иконка, одна строка, уверенность, качество записи, приоритет с основанием.
- **Журнал и проверки:** `/admin/logs` (только чтение, по `ADMIN_TOKEN`): ходы, шаги с моделями, токенами и ₽, сводка за сегодня, 7 дней или всё время. Прогоны проверки `POST /admin/eval` асинхронные, результат пишется в Postgres.

## Запуск локально

Нужны Docker и Docker Compose.

```bash
cp .env.example .env
# в .env заполнить NEURALDEEP_API_KEY, POSTGRES_PASSWORD и MATERIALS_URL (файл .env не коммитить)
docker compose -f docker-compose.local.yml up --build
```

В другом терминале загрузить руководства в базу (нужны PDF по `MATERIALS_URL`, индексация идемпотентна):

```bash
docker compose -f docker-compose.local.yml exec app python -m app.rag.ingest
```

Интерфейс: http://localhost:8000/, проверка: `curl http://localhost:8000/health`. Для узкого экрана откройте DevTools и выберите ширину 390 px.

Без Docker нужен Python 3.12:

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
uvicorn app.main:app --reload --port 8000
```

Без `DATABASE_URL` журнал, заявки и диалоги живут в памяти процесса.

## Тесты и линтер

```bash
pytest -q
ruff check .
ruff format --check .
```

Тесты с PostgreSQL запускаются при `TEST_DATABASE_URL`. Тест очищает схему тестовой БД и требует `TEST_DATABASE_ALLOW_RESET=1`. Тесты с настоящими PDF запускаются при `MECHAI_REAL_MATERIALS=1`. Юнит-тесты не ходят в Neuraldeep: клиент моделей подменён. Живой прогон агента и RAG идёт через `POST /admin/eval` на стенде.

## Стек

Python 3.12, FastAPI, Jinja2, HTMX и Alpine.js (мобильный интерфейс), LangGraph, PostgreSQL с pgvector, Pydantic v2, httpx. LLM и речь через Neuraldeep API (openai SDK, `https://api.neuraldeep.ru/v1`), серверы в РФ. Деплой: Docker Compose на Timeweb App Platform. В данных минимум персональных данных: табельный номер, имя по желанию, роль.

## Архитектура и структура

```
app/        FastAPI-приложение: api/ (страницы, /health, /ready, /admin/*), clients/ (ML, ТОиР, моделей, STT),
            data/ (парк ТС), db/ (БД и миграции), rag/ (чанки, поиск, ingest, противоречия), agent/ (агент),
            obs/ (журнал, цены, расход моделей), tools/ (инструменты агента), templates/ и static/ (интерфейс)
mock/       заглушки заказчика (Mock ML, Mock ТОиР, данные). Код не меняем; mock/Dockerfile наш
data/       манифест руководств (manifest.yaml), known_conflicts.yaml. PDF в образ не входят
eval/       сценарии агента, вопросы RAG, отчёты прогонов
scripts/    служебные скрипты: bench_models.py (замер моделей), mobile_check.py (проверка 360–430 px)
tests/      pytest: клиенты против заглушек через TestClient, миграции при TEST_DATABASE_URL
docs/       ТЗ, модели, деплой, промпты фаз, статус проекта, наработки по дизайну
```

Агент: контекст ТС, диагноз и история загружаются кодом до первого вызова модели. Дальше модель сама выбирает `search_manual` и `draft_ticket`. Проверка цитат, порог поиска и отказ «нет данных» выполняются кодом, не промптом. Каждый шаг хода пишется в журнал: модель, токены, миллисекунды, токены в секунду и ₽.

## Заглушки заказчика

- `mock/mock_ml` — `POST /diagnose`, `mock/mock_toir` — `POST /tickets`. Контракт: `mock/openapi_ml.json`, `mock/openapi_toir.json`.
- Адреса только из переменных окружения: `MOCK_ML_URL`, `MOCK_TOIR_URL`.
- Если сеть App Platform не резолвит имена сервисов: `MOUNT_MOCKS=1` (запасной режим, заглушки внутри `app`).

## Материалы задачи

Материалы задачи не лежат в репозитории: требование организатора, п. 9.1. Это заглушки `mock/data/` (`vehicles.json`, `fault_types.json`), PDF руководств и документы заказчика. Ссылка на публичную папку с ними задаётся только в переменных окружения.

- `MATERIALS_URL` — публичная папка с `vehicles.json`, `fault_types.json` и PDF руководств. `MANUALS_URL` и `MOCK_DATA_URL` переопределяют её для PDF и для JSON заглушек. Если отдельных JSON в папке нет, заглушки берут их из архива `MOCK_ARCHIVE_NAME`.
- При старте приложение и заглушки докачивают недостающие JSON. Ошибка пишется в лог, `/health` покажет `materials: missing`, сервис не падает.
- PDF докачиваются при индексации, sha256 проверяется по `data/manuals/manifest.yaml`. Для ответов агента PDF не нужны: фрагменты уже лежат в базе.
- Тесты работают без материалов. Тесты с настоящими PDF помечены `requires_real_materials`.

## Ограничения и не сделано

- **Q03 и Q12 — промахи поиска.** Q03: эталонная страница не проходит порог поиска (подробности в [eval/rag_report.md](eval/rag_report.md)). Q12: эталонная страница 43 не попала в top-5, top-1 — страница 25 (0,985). Не чинились до сдачи.
- **Длинный диалог и заглушка «нет данных».** В длинном диалоге модель может сослаться на страницу из прошлого хода. Проверка цитат принимает только фрагменты текущего хода, поэтому такой ответ заменяется на «В руководстве на <двигатель> этих данных нет». В новом диалоге не воспроизводится. Прошлые ходы-заглушки уже не уходят модели (`recent_messages`, код `a35aa23`).
- **Голос:** русский проверен на стенде (`whisper-1`, фраза с техническими терминами распознана за 1,8 с). Узбекский, казахский, таджикский и киргизский через `whisper-1` не проверены: модель может отказать по коду языка. Многоязычный движок — в плане ниже.
- **Озвучки ответов нет.**
- **PIN-вход и роли не сделаны (этап 09).** `AUTH_MODE=demo`. Датчики и `get_sensor_telemetry` не подключены.
- **Таблицы согласий нет.** Согласие на микрофон хранится в браузере (`voice_consent_at`), сервер проверяет только его наличие. Таблица появится вместе с PIN-входом.
- **Стоимость без реранка.** Сервис реранка не отдаёт число токенов, поэтому его шаги показаны с «—» и в ₽ не входят. Прогоны RAG идут без ₽ и без модели агента.
- **B1–B3 частично.** Сценарий С4 на стенде не проверен полностью.
- **Заявки в прогонах не отправляются.** Прогон агента использует изолированный журнал, черновики живут в памяти прогона.
- **Без `DATABASE_URL`** журнал, заявки и диалоги живут в памяти процесса.
- **Сбой БД журнала во время хода** (`app/agent/runner.py`, вызовы `start_run`/`finish_run`) не перехватывается: поток ответа обрывается, механик видит общую ошибку, ход остаётся незакрытым в журнале.
- **Короткие цитаты руководств в git:** `data/known_conflicts.yaml` (поле `quote`, нужно для блока противоречия), эталоны в `eval/questions.yaml` и отдельные фрагменты в `eval/*_report.md`.
- **Ошибка 422 с массивом в `detail`** отображается в браузере как «[object Object]» (`app/static/js/common.js`); на практике не возникает, поле сообщения ограничено 2000 символами.
- **Разные таймауты агента по умолчанию:** `AGENT_TIMEOUT_S=90` в `.env.example`, 45 в `docker-compose.yml`.
- **Устаревшие ссылки** в `.cursor/rules/tests.mdc` (`eval/run_scenarios.py`, `eval/rag_questions.yaml`, `eval/report.md`) и фраза «проверим после деплоя» в истории `eval/agent_report.md`.
- **Остатки OCR в схеме БД:** таблица `ocr_pages` (миграция 0009) и значение `source='ocr'` у чанков; код OCR удалён.

## Развитие проекта

После MVP планируется (подробности и концепции — в [docs/roadmap/](docs/roadmap/)). Всё перечисленное ниже — план, не реализовано:

- **Концепции мобильного интерфейса.** Пять вариантов экрана механика: индекс состояния, чат с агентом, запись звука, заявка в ТОиР, пошаговый режим для работы у машины.
- **PIN-вход и датчики (этап 09).** Вход по табельному номеру и PIN, адаптер телеметрии `get_sensor_telemetry`.
- **Парк ГАЗель Next.** Расширение на эту линейку пока концепция: в данных проекта таких машин нет, нужны данные парка и руководства.
- **Главный механик (B3) в полном объёме.** Статусы для «Главного механика» по ТЗ §7.3.

### Многоязычный голос для механиков из СНГ (план)

Сейчас в проекте один движок — `whisper-1`. Для узбекского, казахского, таджикского и киргизского качество на нём не проверено, поэтому ниже план, а не готовое решение.

- **Узбекский и казахский:** Yandex SpeechKit с автоопределением ru/uz/kk. Смешанная речь (русские термины внутри узбекской или казахской фразы) распознаётся в одном запросе.
- **Таджикский и киргизский:** self-hosted Meta MMS (`mms-1b-all`) на своём сервере в РФ. Внешних облачных API для этих языков нет.
- **Предобработка звука:** Silero VAD (обрезка тишины) и шумоподавление RNNoise или DeepFilterNet до распознавания.
- **Озвучка ответов:** SpeechKit для uz/kk; `facebook/mms-tts-tgk` и `facebook/mms-tts-kir` для tg/ky, с транслитерацией терминов.
