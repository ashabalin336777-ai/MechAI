# Промпт 2. Postgres, миграции и вход «табельный номер + PIN»

Реализуй схему БД и авторизацию по TZ.md §9 и §13.

Схема (минимум):
- users: tabel (unique), pin_hash, role (мастер|администратор), is_active, failed_attempts, locked_until
- sessions / отзыв JWT по желанию
- agent_traces, defect_drafts, defect_requests, mechanic_answers
- таблицы под LangGraph checkpointer (штатные)
- документы/чанки мануалов и векторные эмбеддинги (pgvector)
- аудит входов и подтверждений заявок

Auth:
- страница входа (русский UI): табельный номер + PIN 4–6 цифр
- хеш argon2id, JWT в httpOnly cookie (CSRF для HTMX) или эквивалент безопасной сессии
- rate limit и блокировка 15 мин после 5 неверных попыток / 10 мин
- роль из сессии доступна зависимостям FastAPI
- администратор может создать пользователя и сбросить PIN (простые формы)
- seed пользователей читает табельные номера и PIN **только из переменных окружения**

Тесты: верный/неверный PIN, lockout, администратор не проходит проверку «можно submit».

Не пиши граф агента в этой фазе.
