## Принятые решения

- **Инъекция в данных.** Тексты из заглушек и руководств (`description`, `anomaly_title`, фрагменты RAG) передаются модели только как данные, в блоке `<tool_data>`. Вердикт и заявку определяют поля `status`, `anomaly_type`, `anomaly_score`, `confidence`, `signal_quality` и результат RAG, а не текст. Попытка команды в данных пишется в журнал событием `prompt_injection_detected`. Контрольный кейс: `T792HO98` / `S-0043`. Статус: реализовано в фазе 04 (маркеры в журнале, данные в `<tool_data>`). Данные заглушки не меняем.
- **Нет заявки без инструкции.** Заявка в ТОиР не создаётся, если: статус `check_failed` или `normal`, нет ссылок из RAG в этом диалоге, ответ «нет инструкции в руководстве этого двигателя», нет подтверждения механика. Повтор `confirm_token` не создаёт вторую заявку. Статус: реализовано в фазе 04 (тесты `test_agent_guards.py`, `test_agent_tools.py`, `test_chat_api.py`).
- **`RAG_MIN_SCORE` = 0.80.** Подобран по прогону на стенде 26.11, см. выше. Меняется в `.env` без пересборки.
- **`sslmode=require`.** Строка `DATABASE_URL` всегда в виде `postgresql://…?sslmode=require`. БД в облаке, соединение шифруется. Схема `postgresql+psycopg://` не используется.
- **Пароль БД без спецсимволов.** Рекомендуется пароль только из латинских букв и цифр, чтобы не экранировать символы в строке подключения. Если спецсимволы всё же нужны, их экранируют по таблице из `docs/deploy.md`.
- **`ADMIN_TOKEN`.** Задаётся в секретах App Platform, в git не попадает. Без него `POST /admin/eval` отвечает 404. Сравнение через `hmac.compare_digest`. Временная переменная `INGEST_TOKEN` удалена из панели.
- **Модель агента.** `qwen3.8-flash-next-ru-noreason` (tool loop и стрим, без рассуждений). `qwen3.6-fp8` не берём: рассуждения включены по умолчанию.
- **Публикация руководств.** Основание: Q&A 18 заказчика, а не письменное разрешение. Отражено в `6850a58`.

## Известные проблемы

- **N03: «нет инструкции» проходит порог.** Фаза 04 даёт агенту судить по содержимому фрагментов; eval на стенде проверит ответ. Для `ЗМЗ-40905.10` и вопроса о тепловом зазоре клапанов top-1 фрагмент — «Система охлаждения» (rerank 0.985). Reranker оценивает тематическую близость слабо. Меры для фазы 04: агент сам решает «процедура найдена / нет» по содержимому фрагментов (ТЗ §7.1), и eval проверяет ответ, а не только порог. Возможна и детерминированная проверка: фрагмент должен содержать ключевые термины вопроса.
- **Q02 и Q03: промах hit@5.** Эталонная страница 267 `yamz236_rk` не попала в топ-5, при этом в выдаче есть фрагменты `236-3902150-Б РЭ`. Возможные причины: длинный раздел с обкаткой, размытый запрос, веса гибрида. Проверить после появления доступа к БД и модели с рабочей машины или на стенде.
- **Neuraldeep недоступен с рабочей машины.** Таймауты TLS при обращении к `api.neuraldeep.ru`. Поэтому замер моделей неполный (`eval/bench.md`), а прогон eval возможен только с самого стенда.
- **Стенд недоступен с рабочей машины.** Поэтому эндпоинт `/admin/eval` вызывает пользователь, со своим `ADMIN_TOKEN`.
- **Порт 8000 на рабочей машине занят Docker Desktop** (`com.docker.backend`, `wslrelay`). Запросы с хоста к `localhost:8000` рвутся, внутри контейнера всё работает. Помогает перезапуск Docker Desktop.
- **Большой PDF не в git.** `yamz-536_rk_2013.pdf` (99 МБ) скачивается скриптом `scripts/fetch_manuals.py` с Яндекс Диска. Загрузка через Яндекс давала незавершённый файл, поэтому файл был заменён локальной копией (sha256 проверен).
- **Шкала rerank score.** Сырые значения в диапазоне 0..1 (подтверждено отчётом 26.11), порог интерпретируется как доля.
