## Принятые решения

- **Инъекция в данных.** Тексты из заглушек и руководств (`description`, `anomaly_title`, фрагменты RAG) передаются модели только как данные, в блоке `<tool_data>`. Вердикт и заявку определяют поля `status`, `anomaly_type`, `anomaly_score`, `confidence`, `signal_quality` и результат RAG, а не текст. Попытка команды в данных пишется в журнал событием `prompt_injection_detected`. Контрольный кейс: `T792HO98` / `S-0043`. Статус: решение принято, реализация запланирована в фазе 04 (`injection_guard`). Данные заглушки не меняем.
- **Нет заявки без инструкции.** Заявка в ТОиР не создаётся, если: статус `check_failed` или `normal`, нет ссылок из RAG в этом диалоге, ответ «нет инструкции в руководстве этого двигателя», нет подтверждения механика. Повтор `confirm_token` не создаёт вторую заявку. Статус: решение принято, реализуется в фазе 04.
- **`sslmode=require`.** Строка `DATABASE_URL` всегда в виде `postgresql://…?sslmode=require`. БД в облаке, соединение шифруется. Схема `postgresql+psycopg://` не используется.
- **Пароль БД без спецсимволов.** Рекомендуется пароль только из латинских букв и цифр, чтобы не экранировать символы в строке подключения. Если спецсимволы всё же нужны, их экранируют по таблице из `docs/deploy.md`.
- **`ADMIN_TOKEN`.** Задаётся в секретах App Platform, в git не попадает. Без него `POST /admin/eval` отвечает 404. Сравнение через `hmac.compare_digest`. Временная переменная `INGEST_TOKEN` удалена из панели.
- **`RAG_MIN_SCORE`.** Пока 0.35. Подбирается по первому прогону на стенде, не по догадке.
- **Модель агента.** `qwen3.8-flash-next-ru-noreason` (tool loop и стрим, без рассуждений). `qwen3.6-fp8` не берём: рассуждения включены по умолчанию.
- **Публикация руководств.** Основание: Q&A 18 заказчика, а не письменное разрешение. Отражено в `6850a58`.

## Известные проблемы

- **Neuraldeep недоступен с рабочей машины.** Таймауты TLS при обращении к `api.neuraldeep.ru`. Поэтому замер моделей неполный (`eval/bench.md`), а прогон eval возможен только с самого стенда.
- **Стенд недоступен с рабочей машины.** Поэтому эндпоинт `/admin/eval` вызывает пользователь, со своим `ADMIN_TOKEN`.
- **Большой PDF не в git.** `yamz-536_rk_2013.pdf` (99 МБ) скачивается скриптом `scripts/fetch_manuals.py` с Яндекс Диска. Загрузка через Яндекс давала незавершённый файл, поэтому файл был заменён локальной копией (sha256 проверен).
- **Шкала rerank score не проверена.** Если `relevance_score` не в диапазоне 0..1, порог 0.35 нужно пересмотреть.
- **Фаза 04 не начата**, поэтому инъекции и проверки заявок пока не реализованы в коде, только в ТЗ.
