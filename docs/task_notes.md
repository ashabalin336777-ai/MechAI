# Выводы по задаче (своими словами)

Документы заказчика не лежат в репозитории (требование организатора, п. 9.1). Здесь только наши выводы: без копий, цитат и таблиц из материалов задачи. Точные значения берутся из материалов при деплое по ссылке `MATERIALS_URL`.

- **Что делаем.** Помощник механика по диагностике двигателя: по записи диагностики от модели-заглушки (ML) и руководству на конкретный двигатель даёт вердикт, этапы проверки и ссылки на страницы руководства. Заявку в ТОиР создаём только по команде механика.
- **Источник фактов.** Только руководство на двигатель, который стоит на ТС (связка по `engine_model`). Цифры с единицами сопровождаются ссылкой на страницу PDF. Если в руководстве нужных данных нет, отвечаем «в руководстве на этот двигатель этих данных нет» и рекомендуем дефектовку.
- **Статусы диагностики.** `normal`, `anomaly`, `check_failed`. При `check_failed` или плохом качестве записи выводов о двигателе нет и заявку не создаём.
- **Интеграции.** Заглушки ML и ТОиР вызываем по контрактам OpenAPI заказчика. Адреса берём только из переменных окружения.
- **Приоритеты.** Сначала обязательный минимум F1–F7 и сценарии С1–С3 на стенде, затем B1–B3, затем пожелания.
- **Данные в репозитории.** Только синтетика для тестов (`tests/fixtures/mock_data/`), с пометкой «тестовые данные». Настоящие данные подтягиваются при деплое.
- **Персональные данные и голос.** Хостинг и модели в РФ. Храним минимум ПДн. Голосовые записи не сохраняем, только распознанный текст.
