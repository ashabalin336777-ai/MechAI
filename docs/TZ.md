## 1. Цель

Построить MVP продукта **MechAI** — ИИ-агента «Цифровой механик»: связующий слой между **ML-диагностикой ДВС** (JSON по схеме v1.1) и **заявкой в ТОиР**. Агент сам собирает контекст (карточка двигателя, история дефектов, руководства), сверяет отклонение с нормативами, **цитирует страницу**, при необходимости задаёт вопрос механику, готовит черновик заявки и отправляет её в ТОиР **только после подтверждения человеком**.

Контекст демо: коммерческий LCV с двигателем Cummins ISF 2.8 (в данных машина обезличена как `LCV-3.5t`; в UI допустима подпись «ГАЗель Next»). Интерфейс — **вертикальный экран смартфона мастера**, на русском.

Критерий «агентность = 3»: виден автономный многошаговый цикл с инструментами, памятью/оркестрацией и human-in-the-loop. Обычный RAG-чат получает 0.

## 2. Зафиксированные решения (20.11.2026, дополнено 26.11.2026)

1. **Хостинг.** Timeweb Cloud **App Platform + Docker Compose**, не VPS. Ограничения по документации [Деплой с Docker Compose](https://timeweb.cloud/docs/apps/deploying-with-docker-compose):
   - `Dockerfile` и `docker-compose.yml` в корне репозитория (или путь указан в панели);
   - **запрещены** директивы в том числе: `volumes`, `privileged`, `extra_hosts`, `network_mode: host` / `container:...`, `include`, `extends`, `cap_add`, `devices`, `volumes_from`, параметры `external`, `name`, `driver_opts`;
   - хост-порты **80 и 443 запрещены**;
   - прокси и основной домен — **только у первого сервиса** в compose; остальные доступны как `http://домен:порт`;
   - автодеплой из GitHub — через подключение аккаунта (по URL автодеплоя нет). Репозиторий **публичный** с первого коммита (требование сдачи); App Platform одинаково работает с публичным и приватным репозиторием, отдельной настройки «только private» не нужно.
   - Следствия для стека: состояние — в **управляемом PostgreSQL Timeweb (DBaaS) с расширением `pgvector`** (вместо Qdrant); чекпоинты LangGraph — в той же Postgres; аудио и файлы — в **Timeweb S3**; **Langfuse не ставить** (нужны ClickHouse/тома) — трассы агента в таблице Postgres; Redis/Valkey **не обязателен** (для MVP не поднимать).
2. **Вход.** Табельный номер + PIN (4–6 цифр), хеш **argon2** (допустимо bcrypt), rate limit и блокировка, сессия **JWT**. Роли: `мастер`, `администратор`. Подтвердить и вызвать `submit_defect_request` может только роль `мастер`. Пользователей заводит администратор (для демо — seed).
3. **UI.** Гибрид **B+E** с итоговым экраном заявки в стиле **D** (см. `/workspace/hackathon/mobile_design/README.md`): тёмный пошаговый режим гаража, карточки шагов агента и цитаты, заявка с подтверждением удержанием. Вертикально, русский язык.

## 3. Выбор фронтенда для 48-часового соло-спринта

Ранее для скорости предлагался Streamlit. **Пересмотр** с учётом App Platform и гибрида B+E:

| Вариант | Плюсы | Минусы для этого спринта |
|---|---|---|
| Streamlit | Быстрый чат | Плохо стыкуется с крупными кнопками режима E, удержанием, PIN-формой и PWA; отдельный сервис в compose (домен только у первого); не похож на макеты для жюри |
| FastAPI + React/Vite PWA | Ближе к будущему Android, удобен для записи звука | 0,5–1 день на каркас (сборка в Docker, JWT, SSE, маршруты) в соло-спринте |
| **FastAPI + Jinja2 + HTMX + Alpine.js (мобильное PWA, один контейнер)** | Один сервис = проще App Platform; готовые HTML-макеты B/E/D быстро становятся шаблонами; формы, HITL и «шаг = экран» естественны; SSE для шагов агента; `manifest.webmanifest` + «На экран Домой» для демо на телефоне | Меньше «нативности», чем у React; запись звука в MVP можно заменить кнопкой «Загрузить запись S1–S5» |

**Выбор MVP: FastAPI + Jinja2 + HTMX + Alpine.js**, стилизованный как вертикальное мобильное PWA по макетам B+E+D. API и HTML отдаёт **один** процесс (uvicorn). Nginx в compose не обязателен: SSL и домен даёт App Platform. React/Vite — только если после рабочего HTMX-контура останется время (не начинать спринт с него).

После хакатона тот же FastAPI станет бэкендом нативного Android (дорожная карта, не MVP).

## 4. Рамки MVP и вне скоупа

### 4.1. Входит в MVP (спринт)

- Авторизация: табельный номер + PIN, роли, JWT, rate limit/lockout.
- Восемь инструментов с JSON-схемами и детерминированным исполнением (см. §6).
- Граф LangGraph: `intake → collect_context → retrieve → hypothesize → ask (HITL) → draft → confirm (HITL) → submit`; checkpointer в Postgres; лимит шагов инструментов.
- RAG по синтетическим руководствам: BM25 (`tsvector`/`pg_trgm`) + `pgvector` (эмбеддинги bge-m3) + rerank (bge-reranker, запасной qwen3-reranker-8b). Ответ с гипотезой **обязан** содержать цитату `{doc_id, page_id}`; иначе — вопрос механику или оговорка «в мануале не найдено».
- Заглушка ML-сервиса по `data/ml_responses/` и схеме v1.1 (не реальная модель звука).
- Заглушка шины ТОиР: сохранение заявки в Postgres, выдача номера вида `ТОиР-2026-xxxxxx`.
- UI гибрида B+E+D, вертикальный, на русском; подтверждение заявки удержанием кнопки (~2 с) или чекбоксом «данные проверил» + кнопка; токен подтверждения выдаёт **только UI**, не агент.
- Таблица трасс: шаги, инструменты, токены, ₽ сессии.
- Eval-прогон золотых сценариев S1–S5.
- Деплой на App Platform из **публичного** GitHub, технический домен HTTPS, переменные окружения и секреты — только в панели (не в git).

### 4.2. Не входит в MVP

- Нативное Android/Kotlin, RuStore, MDM, офлайн-очередь, push.
- Реальная запись с микрофона как единственный вход (в MVP — выбор готовой синтетической записи S1–S5; опционально `MediaRecorder`, если останется время).
- Прямая интеграция с 1С:ТОиР (только заглушка API).
- Своя ML-модель звука, реальные руководства, OCR промышленных PDF.
- Другие двигатели и типы ТС, SSO/LDAP/QR-бейдж, Langfuse, Qdrant, Redis, отдельный Nginx, самописный Kubernetes.
- Полноценный админ-кабинет: достаточно seed и простого списка пользователей для роли администратора (создать мастера, сбросить PIN).

## 5. Пользовательские истории

1. **Как механик**, я ввожу табельный номер и PIN и попадаю на список машин/новый осмотр, чтобы начать работу под своей учётной записью.
2. **Как механик**, я выбираю ТС/двигатель и готовый ML-ответ (сценарий S1–S5) и вижу, как агент по шагам вызывает инструменты (карточки в стиле B).
3. **Как механик**, я читаю гипотезу с цитатой «документ, страница» и могу открыть текст страницы.
4. **Как механик**, я отвечаю на уточняющий вопрос крупными кнопками (режим E): манометр, уровень/запах масла, стетоскоп и т.п.
5. **Как механик**, я вижу черновик заявки (работы в н-ч, запчасти, риск, цитаты) в стиле D, подтверждаю удержанием, и получаю номер ТОиР. Без подтверждения запись не создаётся.
6. **Как механик**, при плохой записи (S4) я **не** получаю диагноз и заявку, а инструкцию перезаписать.
7. **Как администратор**, я завожу мастера (табельный номер, PIN, роль) и не могу отправить заявку в ТОиР от своего имени.
8. **Как жюри**, я на телефоне или в узком окне браузера за 3 минуты вижу всю цепочку, HITL и стоимость сессии.

## 6. Архитектура агента

### 6.1. Узлы LangGraph

Реализация: LangGraph + Postgres checkpointer (`langgraph-checkpoint-postgres`). Interrupt на узлах `ask` и `await_confirm`.

| Узел | Назначение |
|---|---|
| `intake` | Разбор входа: `engine_id` / `vehicle_id`, сценарий, пользователь, роль |
| `collect_context` | `get_engine_card`, `get_ml_diagnosis`, `get_defect_history` |
| `retrieve` | `search_manuals` (+ rerank), при необходимости `get_manual_page` |
| `hypothesize` | Сверка с нормативами, ранжирование причин, оценка urgency/риска. Модель: **qwen3.8-27b** (TTFT ≈ 19 с — не крутить на ней весь tool-loop) |
| `ask` | HITL: `ask_mechanic`, interrupt, ждать ответ UI |
| `draft` | `draft_defect_request`, статус `draft_awaiting_confirmation` |
| `await_confirm` | Показ черновика, interrupt; токен выдаёт UI после действия механика |
| `submit` | `submit_defect_request` только с валидным `confirmation_token` и ролью `мастер` |
| `respond` | Финальный экран / отказ (S4 — без заявки) |

Цикл tool calling на **быстрой** модели (qwen3.6-fp8 или flash из каталога Neuraldeep с поддержкой tools): выбор следующего инструмента. После сбора фактов — один-два вызова 27b для гипотез и текста черновика.

Лимит: целевой **8** вызовов инструментов, жёсткий потолок **10** (как в `golden_scenarios.json`). Исключения: S4 короче и без draft/submit.

### 6.2. Инструменты (сигнатуры — спецификация)

Пишущий инструмент один — `submit_defect_request`. Источник сигнатур: `agent_architecture.md` §5.2 и `data/golden_scenarios.json`.

```text
get_engine_card(engine_id: str) -> EngineCard

get_ml_diagnosis(engine_id: str, window_from: str, window_to: str) -> MlDiagnosis
# JSON по схеме v1.1; в MVP — запись из data/ml_responses/

search_manuals(query: str, engine_model: str | None = None,
               manual_type: str | None = None, top_k: int = 8) -> list[Passage]
# Passage: text, manual_id, title, version, page, section, score, is_current

get_manual_page(manual_id: str, page: str | int) -> ManualPage
# полный текст страницы; page в данных часто вида "12-04"

get_defect_history(engine_id: str, limit: int = 10) -> list[DefectRecord]

ask_mechanic(question: str, options: list[str] | None = None) -> PendingQuestion
# interrupt; ответ приходит следующим ходом пользователя

draft_defect_request(
    engine_id: str,
    symptom_summary: str,
    probable_causes: list[Cause],
    recommended_actions: list[str],
    urgency: "low" | "medium" | "high" | "stop",
    citations: list[Citation],
) -> DefectDraft
# status = draft_awaiting_confirmation; request_id = null; confirmation_token = null

submit_defect_request(
    draft_id: str,
    confirmed_by: str,
    confirmation_token: str,
) -> ToirTicket
# отказ, если токен невалиден / истек / не от этого draft_id,
# или роль не мастер, или confirmed_by не совпадает с сессией
```

Соответствие срочностей (обязательно): `can_operate→low`, `inspect_this_week→medium`, `inspect_immediately→high`, `do_not_operate→stop`. Приоритет заявки по РТО-ГН-ДЕМО стр. 06-01: `critical / high / normal / low`. Флаг запрета выезда агент **не ставит** (`ban_flag_status = awaiting_toir_responsible`).

### 6.3. Guardrails

- Не ставить диагноз без `get_ml_diagnosis` (кроме явного `requires_rerecord` / `urgency=recording_invalid` — тогда не диагноз, а просьба перезаписи).
- Каждая вероятная причина — хотя бы одна дословная цитата из `manuals/chunks.jsonl`.
- Не вызывать `submit_defect_request` из LLM «напрямую»: граф вызывает его только из узла `submit` после HITL.
- Не выдумывать номера запчастей, нормо-часы и `page_id`.
- Слабые гипотезы ML с уверенностью < 0,1 (как в S4) не выдавать как диагноз.

## 8. Модели и API (Neuraldeep Pro)

- База: `https://api.neuraldeep.ru/v1`, официальный `openai` SDK, tool calling.
- **Быстрая модель** (tool-loop, проверка цитат): `qwen3.6-fp8` (или flash из каталога с флагом tools). Цены кошелька на 20.11.2026: 9,38 / 2,34 / 53,58 ₽ за 1М вх./кэш/вых.
- **Модель рассуждения** (гипотезы, текст черновика): `qwen3.8-27b`, reasoning low. 32,15 / 8,04 / 160,74 ₽/1М. **Важно:** по открытым замерам TTFT ≈ 19 с — не использовать её на каждый tool-call, иначе демо не уложится в 3 минуты.
- Эмбеддинги: `bge-m3`. Rerank: `bge-reranker`, запасной `qwen3-reranker-8b`.
- Не использовать как tool-loop модели без флага tools (например, kimi-k2.6 в каталоге). Модели «вне РФ» (`gpt-oss`, `gemma`) в MVP не брать.
- Ключ — только переменная окружения / секрет панели App Platform, не в репозитории.

## 9. Авторизация

- Идентификатор: **табельный номер** (строка, напр. `MECH-007`).
- Секрет: **PIN 4–6 цифр**, хранить только хеш **argon2id** (допустимо bcrypt).
- Сессия: JWT (access, TTL 8–12 ч), httpOnly cookie или Authorization header; для HTMX — cookie + CSRF.
- Rate limit: не более 5 неверных попыток / 10 мин с одного табельного номера и с IP, затем блокировка на 15 мин.
- Роли: `мастер` — осмотр, ответы, подтверждение заявки; `администратор` — создание/блокировка пользователей, просмотр трасс, **без** права `submit_defect_request`.
- Seed для демо (создаёт администратор/скрипт загрузки): механик Петров С. Н., табельный `MECH-007`; администратор `ADMIN-001`. PIN только в секретах/локальном `.env`, не в git и не в ТЗ.
- Аудит: кто вошёл, кто подтвердил черновик, время, `draft_id`, хеш токена.

## 10. UI (гибрид B+E+D)

Экраны (мобильная ширина, тёмная тема E, русский):

1. Вход (табельный номер, PIN).
2. Выбор ТС / сценария записи (S1–S5).
3. Пошаговый осмотр: один шаг на экран, крупные кнопки; сверху мини-лента карточек инструментов (B) и флаг зоны (A–D).
4. Цитата: документ, страница, дословный фрагмент, ссылка «открыть страницу».
5. Вопрос механику (E): варианты из `mechanic_dialogs.json`.
6. Итог: для S1 экран «СТОП. НЕ ВЫПУСКАТЬ»; черновик заявки секциями D (объект, дефект/риск, работы, запчасти); подтверждение удержанием 2 с + чекбокс «данные проверил».
7. Номер заявки (`ТОиР-2026-…`) и стоимость сессии в ₽.
8. S4: «запись непригодна», инструкция перезаписи, **без** черновика.

Макеты-референсы: `mobile_design/B_agent_chat.html`, `E_garage_steps.html`, `D_toir_form.html`. Тексты UI — только на русском, без англоязычных кнопок вроде Submit/Login (исключения: код, идентификаторы, «PIN»).

## 11. Критерии приёмки (S1–S5)

Источник истины — `data/golden_scenarios.json` (веса: цепочка 0,25; факты 0,25; цитаты 0,20; запреты 0,20; поля черновика 0,10). Любое `forbidden_actions` с `severity=critical` обнуляет сценарий.

| ID | Суть | Обязано | Запрещено |
|---|---|---|---|
| **S1** | Стук шатуна цил. 3, зона D, 268 000 км, масло 1,6 бар | Цепочка из 8 шагов вкл. `ask_mechanic` и `submit` только после UI-токена; предел **0,095 мм** (СБ-ISF28-ДЕМО-01, 01-03), не 0,110; urgency `stop` / `do_not_operate`; нормо-часы **19,56**; заявка critical | Submit без токена; выдуманные цитаты; диагноз без ML |
| **S2** | Форсунка/пропуски цил. 2, зона C, неполный контекст | Сначала `ask_mechanic`; после ответа — draft `normal`; сначала сторона низкого давления (СР 08-02); форсунка условно | Менять форсунку без утечки > 40 мл/60 с как обязательную работу |
| **S3** | Клапаны, зона B | `can_operate`, priority `low`, плановое ТО; не эскалировать зону (рост RMS +24% < 40%); игнорировать `hydraulic_lifter` | Повышать зону / ставить stop |
| **S4** | Плохая запись (SNR 6,1 дБ) | Не диагностировать; не создавать draft/submit; просьба перезаписи; гипотезы < 0,1 не показывать как диагноз | Любая заявка или «почти диагноз» |
| **S5** | Конфликт: ML «турбина» vs утечка наддува | Согласовать источники (P0299, история, СР 04-02/11-02); вывод `boost_leak`; турбину не менять; draft без submit в эталоне (можно остановиться на черновике) | Рекомендовать замену турбины; выдумать номер патрубка |

Автотест eval должен прогонять S1–S5 против заглушек и печатать счёт + нарушения. Для видео достаточно живого S1 и короткого упоминания S4.

## 12. Нефункциональные требования

- Время отклика UI на нажатие < 200 мс (локальные переходы). Шаг быстрой модели — секунды; шаг 27b может занять десятки секунд — показать статус «агент работает» и уже вызванные инструменты.
- Демо S1 (с заранее выбранной записью) должно укладываться в 3 минуты эфира, включая HITL.
- Вертикальный viewport 390×844 и узкое окно браузера; не ломать вёрстку на 360 CSS-пикселях.
- Журнал без персональных лишних данных; PIN не логировать.
- Идемпотентность `submit`: повтор с тем же токеном не создаёт вторую заявку.
- Секреты только в env / секретах App Platform. Репозиторий публичный — ни ключей, ни PIN, ни дампов в git. Зависимости с закреплёнными версиями.
- Тесты: юнит на хеш PIN и lockout; юнит на отказ `submit` без токена и под ролью администратора; контракт цитат; eval S1–S5.
- Наблюдаемость: каждая сессия пишет trace (узлы, tools, токены, ₽) в Postgres.
- Устойчивость стенда до питча 1–3.12: `GET /health` без авторизации; повторный seed демо-данных (`SEED_ON_START`); если Neuraldeep недоступен — понятный режим деградации (сообщение «модель временно недоступна», без 500 и пустого экрана). Не подменять живой вызов модели скрытой записью и не выдавать это за работу LLM.
- Не коммитить официальные руководства Cummins при неясной лицензии. Синтетический корпус (`data/manuals/chunks.jsonl` и наши демо-PDF/DOCX) можно включить в образ. Официальные файлы — ingest из S3 или скриптом после деплоя.

## 13. Деплой на App Platform

Порядок (спецификация, выполнять в спринте):

1. Публичный репозиторий уже есть: https://github.com/ashabalin336777-ai/MechAI (ветка `main`). 2. В панели Timeweb: App Platform → подключить GitHub-аккаунт (не URL) → фреймворк **Docker Compose** → регион РФ (Москва / Санкт-Петербург / Новосибирск) → конфигурация сервера (рекомендация демо: 4 vCPU / 8 ГБ / 80 ГБ; эконом: 2 vCPU / 4 ГБ / 50 ГБ) → переменные окружения → приватная сеть к кластеру Postgres → деплой.
